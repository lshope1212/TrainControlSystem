# CSV FORMAT

For this iteration, schedules use this format:

```csv
Line,Section,Block Number,Train 1,Train 2,Train 3,Train 4
Blue,A,1,12:00:00,12:03:00,12:06:00,12:09:00
Blue,B,10,12:00:36,,12:06:36,
Blue,C,15,,12:03:36,,12:09:36
```

The first three columns are required:

```text
Line
Section
Block Number
```

Every remaining column represents one train.

For example:

```text
Train 1
Train 2
Train 3
Train 4
```

The actual text of the train column headers is only descriptive.

DO NOT use those strings as the real CTC TrainIds.

CTC must continue generating TrainIds using its existing mechanism:

```csharp
TrainIds.NextAvailableNumber(_ctc.State)
```

and:

```csharp
ScheduleTemplateFactory.Create(...)
```

For example, if four train IDs are currently available starting at 000, the imported columns become:

```text
Train 000
Train 001
Train 002
Train 003
```

regardless of the CSV header labels.

# IMPORTANT: SPARSE SCHEDULE FORMAT

The CSV intentionally does NOT need one row for every track block.

It contains only blocks at which the dispatcher explicitly specifies a time.

For example, the provided Blue Line schedule contains:

```text
A1
B10
C15
```

but the actual Blue Line contains all 15 blocks.

The importer must therefore:

1. Generate a complete `ScheduleTemplate` using the current selected line and `ScheduleTemplateFactory`.
2. Match each CSV row to its corresponding generated template row.
3. Copy the train times from the CSV into that row's `TrainTimes[]`.
4. Leave every other generated block row blank.

This allows the existing `ScheduleTemplateConverter` to determine the route through the untimed intermediate blocks.

DO NOT construct routes in the CSV importer.

Routing remains the responsibility of the existing scheduling code.

# IMPORT PROCESS

The importer should do approximately this:

## 1. Parse header

Require at least:

```text
Line,Section,Block Number,<one train column>
```

There must be at least one train column.

All columns after `Block Number` represent trains.

Ignore leading/trailing whitespace around textual fields.

Blank lines in the CSV should be ignored.

---

## 2. Validate line

The CSV's Line field must correspond to the currently selected line.

For this iteration the selected line will normally be:

```text
LineId = BLUE
Name = Blue Line
```

The CSV uses:

```text
Blue
```

Accept reasonable case-insensitive equivalents such as:

```text
Blue
BLUE
Blue Line
```

Do not allow a Red or Green schedule to populate the Blue Line builder.

Return a clear error such as:

```text
Schedule is for Red Line, but Blue Line is currently selected.
```

---

## 3. Determine train count

The number of train columns determines the number of trains.

Example:

```text
Line,Section,Block Number,Train 1,Train 2,Train 3,Train 4
```

means:

```text
trainCount = 4
```

---

## 4. Generate the real template

Use the existing factory:

```csharp
int firstTrainNumber = TrainIds.NextAvailableNumber(_ctc.State);

ScheduleTemplate template =
    ScheduleTemplateFactory.Create(
        line,
        trainCount,
        firstTrainNumber);
```

Do not manually duplicate track information from the CSV.

Properties such as:

- BlockId
- Section
- block number
- length
- infrastructure
- station name
- speed limit
- connections
- route start

must continue coming from the currently loaded CTC track layout.

---

## 5. Match CSV rows to blocks

Each CSV row identifies a block using:

```text
Section + Block Number
```

For example:

```text
A,1
B,10
C,15
```

Find the corresponding generated `ScheduleTemplateRow`.

Do not assume BlockId format unless necessary. Prefer matching the existing row using its:

```csharp
Section
BlockNumber
```

properties.

Matching Section should be case-insensitive.

---

## 6. Copy train times

For every train column:

```csharp
templateRow.TrainTimes[column] = importedValue;
```

Blank cells should remain:

```csharp
string.Empty
```

Do not invent or interpolate arrival times.

Do not calculate intermediate block times.

Do not build routes here.

That is handled by the existing converter.

### No train columns

```text

```

### Invalid block number

```text

```

### Unknown block

Example:

```text

```

### Duplicate block rows

Example:

```text

```

### Wrong line

Example:

```text

```

### Inconsistent row column counts / malformed CSV

Return a readable error rather than crashing the application.
