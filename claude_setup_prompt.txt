==================================================

6. CALCULATE INITIAL SUGGESTED SPEED AT DISPATCH
==================================================

When a queued train becomes due, CTC should calculate its initial Suggested Speed.

The calculation should target the NEXT scheduled block.

At actual dispatch time:

    currentTime = CTC system time
    nextArrival = scheduled arrival time of BlockTimes[1]

    remainingSeconds = nextArrival - currentTime

    requiredSpeed =
        startBlock.LengthMeters / remainingSeconds

    effectiveMaximum =
        min(block speed limit, physical train maximum)

    suggestedSpeed =
        min(requiredSpeed, effectiveMaximum)

This protects the system if the simulation clock advanced slightly beyond the planned departure time.

If remainingSeconds <= 0, the train is already late. Do not create an infinite/negative speed. Use the maximum safe permitted speed and surface a useful status/warning.

For this iteration we only need the INITIAL suggested speed at dispatch.

Do not attempt continuous speed recalculation after the train moves because CTC currently has no reliable train-specific block-location update.

7. IMPLEMENT INITIAL SUGGESTED AUTHORITY
==================================================

Implement a simple fixed-block authority algorithm appropriate for this iteration.

Authority means:

    "The distance the train may travel along ITS SCHEDULED ROUTE
     before reaching the first block it must not enter."

Starting from the train's route-start/current block, walk forward through its scheduled route.

A block ahead is unsafe if, at minimum:
- Occupancy == Occupied
- CTC has requested that the block be Closed for maintenance

Stop the authority at the boundary BEFORE the first unsafe block.

SuggestedAuthorityMeters should equal the sum of the traversable block lengths from the train's current position through the last safe block.

Example with 50 m blocks:

    B1 clear
    B2 clear
    B3 occupied

Suggested authority = 100 m.

If the current/start block itself is unusable, do not dispatch with a positive authority.

If no route block ahead is blocked, authority may extend to the end of the scheduled route.
