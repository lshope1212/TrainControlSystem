CTC SERVICE
----------------------------------------------------------------------

Reuse the existing ICTCService and CTCService structure.

Add a CTC operation for closing a block.

Prefer:

    Task CloseBlockAsync(
        string blockId,
        CancellationToken cancellationToken = default);

or an equivalent name that fits the existing service design.

The method should:

1. Reject null/empty/whitespace BlockId.

2. Locate the corresponding CTC block in the current CTC system state.

3. Throw an appropriate exception if the block does not exist.

4. Create:

       new MaintenanceRequestMessage
       {
           BlockId = blockId,
           RequestedState = MaintenanceState.Closed
       }

5. Send that message using the injected IMessageSender.

6. Only after the send completes successfully, update CTC's LOCAL/REQUESTED
   maintenance state for that block to Closed, if such a property currently
   exists.

IMPORTANT:

This local maintenance state is NOT confirmation that Track Controller actually
closed the block.

It only means:

    "CTC successfully issued a request for this block to be closed."

Document this clearly in the code.

If the current model already uses a property such as:

    RequestedMaintenanceState

reuse it.

If the model uses another sensible name, do not rename things unnecessarily.

Do not invent Track Controller acknowledgement behavior.

NAMED PIPE IMPLEMENTATION
----------------------------------------------------------------------

For this task, use Windows Named Pipes as the concrete outgoing transport.

Implement the sender in the CTC WPF project, NOT CTC.Core.

Suggested location:

    src/CTC/CTC.Wpf/Services/NamedPipeMessageSender.cs

Use only .NET built-in libraries:

- System.IO.Pipes
- System.Text.Json

Do not add third-party packages.

Use this pipe name as a single constant:

    TrainControl.TrackController

Do not scatter this string throughout the application.

The sender should:

1. Create a NamedPipeClientStream targeting the local machine:

       serverName = "."
       pipeName = "TrainControl.TrackController"

2. Open it for output.

3. Use asynchronous mode.

4. Attempt to connect with a reasonable timeout, approximately 2-3 seconds.

5. Serialize the outgoing message to JSON.

6. Write one complete newline-delimited JSON message to the pipe.

7. Flush the writer.

8. Dispose the pipe cleanly.

Do NOT keep a permanent background pipe connection yet.

For now, one connection per outgoing request is acceptable and easier to reason
about.

}

The exact C# implementation can be a private/internal transport class inside the
CTC.Wpf sender infrastructure.

Do NOT put named-pipe framing concepts into CTC.Core domain models.

For example:

rather than:

    "requestedState": 1

This will make later Track Controller integration much easier to inspect/debug.
